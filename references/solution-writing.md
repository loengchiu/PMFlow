# Solution 写法参考

本文件承接 OMP 方案稿经验，只做 solution-writer 的写法参考。

## 1. 目标

solution 是当前版本方案稿，不是 PRD，也不是原型说明。

它要回答：

- 本次属于迭代、新建还是混合。
- 做哪些模块。
- 有哪些页面。
- 每个关键页面承担什么。
- 页面需要哪些关键字段或字段分组。
- 用户怎么从入口走到结果。
- 哪些决策已经确定，哪些还待确认。

## 2. 页面展开粒度

### 简单页

适用：

- 普通入口页。
- 普通结果页。
- 只展示少量信息的页面。

写法：

- 1 段说明即可。
- 不硬补字段、动作、约束三件套。

### 中等复杂页

适用：

- 列表页。
- 普通表单页。
- 普通详情页。

写法：

- 页面说明。
- 关键字段或字段分组。
- 关键动作。
- 必要约束。

### 高复杂页

适用：

- 审批页。
- 统计页。
- 多状态流转页。
- 存量承接复杂页。

写法：

- 页面承接完整交代。
- 字段前置。
- 流程口径写清。
- 关键约束写清边界和兼容点。

## 3. 字段前置规则

页面涉及以下任一情况时，字段应在 solution 阶段出现：

- 展示字段决定页面承接。
- 录入字段决定表单范围。
- 筛选字段决定列表或统计设计。
- 统计字段决定口径。
- 存量字段承接不清会影响改造范围。

详情页、表单页、审批页如果承接新增、编辑、详情查看、审批处理，不适合只写页面说明。字段很多时写字段分组，字段较少时写关键字段集。

## 4. 列表页信息架构

列表页不是表单字段平移页。

solution 阶段要先回答：

- 用户进入列表第一眼要判断什么。
- 哪些字段足以定位和判断。
- 默认排序是什么。
- 常用筛选维度是什么。
- 从哪里进入详情、编辑或流程处理。

不要把表单几十个字段搬到列表。列表只展示支持判断和下一步动作的核心字段。

## 5. 流程口径

模块有明显流转时，solution 必须补主流程说明。

页面承接提交、审批、审核、发布、退回、撤回、销号、归档时，必须写流程口径：

- 从哪里进入。
- 提交后到哪里。
- 通过后状态如何变化。
- 驳回或退回后回到哪里。
- 是否涉及角色交接。

## 6. 建设类型

判断建设类型时不要只看“是否新项目立项”。

按部署、代码、数据库、运行实例四个维度判断：

- 都是新的，只参考旧系统字段、流程、页面或文案：新建。
- 在已有系统、代码、数据库、实例上改：迭代。
- 同时存在存量改造和新建独立部分：混合。

## 7. 轻量 ADR

只记录关键方案取舍。

适用：

- BRD/UC 没有明确，但 solution 必须做选择。
- 存在两个以上合理方案。
- 该选择会影响原型、PRD 或研发实现。

不适用：

- 小字段命名。
- 常规按钮位置。
- 无实际影响的文案选择。

ADR 写法：

- 背景。
- 决策。
- 理由。
- 未选方案。
- 影响。
