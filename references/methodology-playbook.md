# 方法论轻量用法

本文件说明 PMFlow 当前允许使用的方法论。方法论用于生成前推导和 review 检查，不直接写进人读产物。

## 1. As-Is / To-Be

适用阶段：

- pm-input
- pm-align
- pm-design

解决问题：

- 旧系统参考
- 迭代改造
- 新旧流程差异
- 建设类型判断

生成前要回答：

- 现状是什么
- 目标状态是什么
- 差异在哪里
- 差异影响哪些模块、页面、字段、流程

输出到哪里：

- input 的材料盘点和建设类型证据
- align 的需求理解和范围边界
- design 的流程、字段、页面和规则设计

## 2. Gap Analysis

适用阶段：

- pm-input
- pm-align-reviewer
- pm-design-reviewer
- pm-prd-reviewer

解决问题：

- 字段缺口
- 流程缺口
- 权限缺口
- 异常缺口
- 数据口径缺口
- 验收缺口

生成前要回答：

- 已知事实是什么
- 缺什么
- 缺口是否阻断下一阶段
- 缺口应该问 PM、写待确认，还是回到上一阶段

输出到哪里：

- open_questions
- reviewer 的 warn/fail
- metadata 的 gaps

## 3. 用户路径 / 任务流

适用阶段：

- pm-align
- pm-design
- pm-wireframe
- pm-prototype

解决问题：

- 谁使用
- 从哪里进入
- 为了完成什么任务
- 经过哪些页面和状态
- 哪些分支会影响设计、PRD 和原型

生成前要回答：

- 角色是谁
- 任务目标是什么
- 起点在哪里
- 关键步骤是什么
- 成功终点是什么
- 失败、驳回、撤回等分支如何回流

输出到哪里：

- align 的用户路径雏形
- design 的系统流程和页面清单
- wireframe 的页面跳转和操作路径
- prototype 的可点击流程

## 4. 信息架构

适用阶段：

- pm-design
- pm-wireframe
- pm-prd
- pm-prototype

解决问题：

- 列表展示哪些字段
- 筛选项怎么取舍
- 详情页怎么分区
- 表单字段怎么分组
- 操作按钮怎么排

生成前要回答：

- 用户第一眼要判断什么
- 哪些字段支持这个判断
- 哪些信息适合列表，哪些适合详情
- 哪些字段同组填写或同组阅读
- 哪些动作是主动作，哪些是次动作

输出到哪里：

- design 的页面和字段设计
- wireframe 的页面区域和信息层级
- PRD 的页面说明和字段清单
- prototype 的布局、字段位置和操作区

## 5. 轻量 ADR

适用阶段：

- pm-align
- pm-design
- pm-prd

解决问题：

- 关键方案取舍
- 建设类型边界
- 页面合并或拆分
- 字段承载位置
- 流程路径选择

生成前要回答：

- 有哪些可选方案
- 选择了哪个
- 为什么
- 未选方案为什么不选
- 影响哪些后续产物

输出到哪里：

- align 的方案方向
- design 的关键设计决策
- PRD 的业务规则和页面说明
