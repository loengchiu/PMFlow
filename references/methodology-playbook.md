# 方法论轻量用法

本文件只解释 PMFlow 当前允许使用的方法论。方法论用于生成前推导，不直接写进人读产物。

## 1. As-Is / To-Be

适用阶段：

- brd-interviewer
- solution-writer
- prd-writer

解决问题：

- 旧系统参考。
- 迭代改造。
- 新旧流程差异。
- 建设类型判断。

生成前要回答：

- 现状是什么。
- 目标状态是什么。
- 差异在哪里。
- 差异影响哪些模块、页面、字段、流程。

输出到哪里：

- solution 的建设类型、模块范围、页面范围。
- metadata 的 build_type_evidence。
- PRD 的范围和业务流程。

不要写到人读产物里：

- “根据 As-Is / To-Be 分析”。
- 方法论过程。

## 2. Gap Analysis

适用阶段：

- brd-interviewer
- uc-interviewer
- solution-writer
- prd-reviewer

解决问题：

- 字段缺口。
- 流程缺口。
- 权限缺口。
- 异常缺口。
- 数据口径缺口。
- 验收缺口。

生成前要回答：

- 已知事实是什么。
- 缺什么。
- 缺口是否阻断下一阶段。
- 缺口应该问 PM、写待确认，还是回到上一阶段。

输出到哪里：

- open_questions。
- reviewer 的 warn/fail。
- metadata 的 gaps。

不要写到人读产物里：

- 大段“差距分析过程”。
- 没有业务价值的缺口表。

## 3. 用户路径 / 任务流

适用阶段：

- uc-interviewer
- solution-writer
- prototype-designer

解决问题：

- 谁使用。
- 从哪里进入。
- 为了完成什么任务。
- 经过哪些页面和状态。
- 哪些分支会影响方案和原型。

生成前要回答：

- 角色是谁。
- 任务目标是什么。
- 起点在哪里。
- 关键步骤是什么。
- 成功终点是什么。
- 失败、驳回、撤回等分支如何回流。

输出到哪里：

- UC note。
- solution 的模块主流程和页面流转。
- prototype 的页面顺序和流程原型。

不要写到人读产物里：

- 方法论名称。
- 与业务无关的泛泛用户旅程描述。

## 4. 信息架构

适用阶段：

- solution-writer
- solution-reviewer
- prototype-designer
- prototype-reviewer

解决问题：

- 列表展示哪些字段。
- 筛选项怎么取舍。
- 详情页怎么分区。
- 表单字段怎么分组。
- 操作按钮怎么排。

生成前要回答：

- 用户第一眼要判断什么。
- 哪些字段支持这个判断。
- 哪些信息适合列表，哪些适合详情。
- 哪些字段同组填写或同组阅读。
- 哪些动作是主动作，哪些是次动作。

输出到哪里：

- solution 的关键字段、字段分组、页面说明。
- prototype 的页面布局、字段位置和操作区。
- reviewer 的信息架构质量检查。

不要写到人读产物里：

- “基于信息架构分析”。
- 没有落到页面的抽象分类。

## 5. 轻量 ADR

适用阶段：

- solution-writer
- solution-reviewer

解决问题：

- 关键方案取舍。
- 建设类型边界。
- 页面合并或拆分。
- 字段承载位置。
- 流程路径选择。

生成前要回答：

- 有哪些可选方案。
- 选择了哪个。
- 为什么。
- 未选方案为什么不选。
- 影响哪些后续产物。

输出到哪里：

- solution 的轻量 ADR。
- metadata 的 decisions。

不要写到人读产物里：

- 小决定。
- 没有实际影响的形式选择。
- 冗长架构决策模板。
