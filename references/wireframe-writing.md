# 线框说明稿写法参考

本文件是 `/pm-wireframe` 的写法参考，只做推荐写法和示例，不替代 skill、profile 或 gate。

## 1. 目标状态

wireframe.md 让 PM 在写 PRD 前验证：

- 页面之间怎么跳转。
- 每个页面由哪些区域组成。
- design 中的字段、操作、状态是否能落到页面上。
- 页面层暴露了哪些设计疑点。

目标不是画出精美线框，而是用最短篇幅让 PM 看懂页面结构并发现问题。

## 2. 页面跳转树写法

页面跳转树用缩进文本表达页面关系。

目标状态：

- 一眼看到从哪个页面可以到哪个页面。
- 主入口、主流程、结果页、返回页都有落点。
- 分支和回退路径清晰。

推荐写法：

```text
P1 触摸屏信息首页
  ├─ 查看信息详情 -> P2 服务区详情页
  ├─ 意见反馈 -> P3 意见反馈填写页
  └─ 满意度调查 -> P7 满意度问卷页

P3 意见反馈填写页
  └─ 提交成功 -> P4 意见反馈提交成功页
       ├─ 返回首页 -> P1 触摸屏信息首页
       └─ 参与满意度调查 -> P7 满意度问卷页
```

写法要点：

- 每个页面只出现一次作为根节点。
- 跳转用 `->` 指向目标页面。
- 按页面编号排序，方便与页面线框章节对应。
- 不需要覆盖所有跳转，重点覆盖主流程和关键分支。

## 3. 主流程说明写法

主流程说明按用户动作和页面流转写成编号步骤。

目标状态：

- PM 能跟着步骤走一遍完整流程。
- 每步知道在哪个页面、用户做什么、系统响应什么。
- 成功和异常路径都有交代。

推荐写法：

```text
流程：意见反馈

1. 用户从 P1 触摸屏信息首页点击"意见反馈"。
2. 系统进入 P3 意见反馈填写页。
3. 用户选择反馈对象。
4. 系统根据反馈对象展示问题类型。
5. 用户选择问题类型，填写补充说明。
6. 用户点击"提交"。
7. 系统校验必填项，提交成功后进入 P4 意见反馈提交成功页。
8. 用户可以返回首页，也可以继续参与满意度调查。
```

写法要点：

- 动作主体写"用户"或"系统"，让读者知道谁在做。
- 每步对应一个页面或一个关键动作。
- 异常路径（校验失败、网络异常、取消）单独写或在对应步骤后补充。
- 不需要写字段细节，字段在落点表中覆盖。

## 4. ASCII 页面结构草图写法

页面结构草图用 ASCII 表达关键页面区域。

目标状态：

- PM 能看到页面由哪些区域组成。
- 关键字段、操作、状态的位置一目了然。
- 不需要精确到像素，只需要区域感。

推荐写法：

```text
P3 意见反馈填写页

┌──────────────────────────────┐
│ 意见反馈                      │
├──────────────────────────────┤
│ 微信授权提示区                │
│ 仅小程序 / 二维码入口显示     │
├──────────────────────────────┤
│ 反馈对象 *                    │
│ [环境卫生] [餐饮服务] [...]   │
├──────────────────────────────┤
│ 问题类型 *                    │
│ 根据反馈对象级联显示          │
├──────────────────────────────┤
│ 补充说明                      │
│ [最多 200 字，选填]           │
├──────────────────────────────┤
│                       [提交]  │
└──────────────────────────────┘
```

写法要点：

- 用 `┌─┐│└─┘` 画区域边界。
- 每个区域写名称，必要时加一行说明。
- 必填字段标 `*`。
- 按钮用 `[按钮名]` 表示。
- 简单页面（纯列表、纯详情）可以不画草图，用 1-2 句话描述区域组成即可。
- 入口页、表单页、结果页、汇总页优先画草图。

## 5. 字段 / 操作 / 状态落点表写法

落点表检查 design 中的关键对象是否能落到页面上。

目标状态：

- 每个关键字段有输入或展示位置。
- 每个关键操作有入口和去向。
- 每个关键状态有展示或处理区域。

推荐写法：

```text
| 类型 | 名称 | 页面落点 | 备注 |
|------|------|----------|------|
| 字段 | 反馈对象 | P3 反馈对象选择区 | 必填 |
| 字段 | 问题类型 | P3 问题类型选择区 | 根据反馈对象级联 |
| 字段 | 补充说明 | P3 补充说明输入区 | 选填，200 字以内 |
| 操作 | 提交 | P3 底部操作区 | 成功后进入 P4 |
| 状态 | 未授权 | P3 微信授权提示区 | 仅小程序 / 二维码入口 |
```

写法要点：

- "页面落点"写页面编号 + 区域名称，让读者能定位。
- "备注"写关键约束或行为，不复制完整规则。
- 同一字段在多个页面出现时，每个页面单独一行。
- 发现字段无落点、操作无入口、状态无展示区域时，记入设计疑点。

## 6. 设计疑点写法

设计疑点记录页面层暴露的问题。

目标状态：

- 问题描述清楚。
- 影响页面和流程明确。
- 为什么在页面层暴露有交代。
- 建议处理指向可执行动作。

推荐写法：

```text
问题：反馈对象与问题类型存在级联关系，但 design 未定义具体映射表。
影响页面：P3 意见反馈填写页、P5 意见反馈汇总页。
影响流程：意见反馈提交、反馈统计。
为什么在页面层暴露：P3 必须根据反馈对象展示问题类型选项，当前无法判断选项集合。
建议处理：回到 design 补充反馈对象与问题类型映射。
```

写法要点：

- 不要直接在疑点中补设计。
- "建议处理"指向 `/pm-design`、`/pm-fix` 或 PM 确认，不指向 wireframe 自身修改。
- 多个疑点按影响严重程度排序。

## 7. 大型需求如何控制长度

页面多时，wireframe.md 容易过长。控制方法：

- **普通列表页**：不画草图，用 1-2 句话描述区域组成，落点表只列关键字段。
- **普通详情页**：不画草图，落点表覆盖展示字段。
- **维护页**：参照表单页模式简写。
- **入口页、表单页、结果页、汇总页**：优先详细展开。
- **页面跳转树**：只覆盖主流程和关键分支，不覆盖所有边缘跳转。
- **主流程说明**：只写 P0/P1 流程，子流程用一句话带过。

目标：PM 能在 10 分钟内读完 wireframe.md 并判断页面结构是否成立。

## 8. 好例子 / 坏例子

### 好：落点表

```text
| 类型 | 名称 | 页面落点 | 备注 |
|------|------|----------|------|
| 字段 | 入库数量 | P2 入库表单-物资信息区 | 必填，正整数 |
| 操作 | 提交入库 | P2 底部操作区 | 校验通过后可点 |
| 状态 | 待审批 | P1 列表-状态列 | 橙色标签 |
```

### 坏：落点表

```text
| 类型 | 名称 | 页面落点 | 备注 |
|------|------|----------|------|
| 字段 | 入库数量 | 表单页 | 必填 |
| 操作 | 提交 | 按钮区 | - |
| 状态 | 状态 | 列表页 | - |
```

问题："页面落点"没有写页面编号和区域名称，无法定位。"备注"没有关键约束。"状态"名称不具体。

### 好：页面跳转树

```text
P1 入库列表页
  ├─ 新增入库 -> P2 入库表单页
  ├─ 查看详情 -> P3 入库详情页
  └─ 导出 -> 下载文件

P2 入库表单页
  └─ 提交成功 -> P1 入库列表页
```

### 坏：页面跳转树

```text
入库列表页可以新增入库、查看详情、导出。新增入库进入入库表单页，提交后返回列表页。查看详情进入详情页。
```

问题：用自然语言描述跳转关系，不如树形结构直观。没有页面编号，无法与后续章节对应。

### 好：设计疑点

```text
问题：design 定义了"审批驳回后退回上一步"，但未定义退回的具体页面和操作。
影响页面：P4 审批详情页。
影响流程：审批驳回流程。
为什么在页面层暴露：P4 需要展示"退回"按钮和退回后的目标页面，当前无法确定。
建议处理：回到 design 补充驳回退回规则。
```

### 坏：设计疑点

```text
审批驳回规则不完整。
```

问题：没有写影响页面、影响流程、为什么在页面层暴露、建议处理。PM 无法判断严重程度和下一步。
